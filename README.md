# 🎲 לשחק בכיתה כי למה לא

אפליקציית משחקי כיתה מרובת משתתפים בזמן אמת, בעברית מלאה.
Node.js + Express + Socket.io בשרת, React (Vite) + Tailwind בלקוח.

## הרצה מקומית

```bash
npm run install:all     # התקנת תלויות בשרת ובלקוח

# בשני טרמינלים:
npm run dev:server      # השרת על פורט 3001
npm run dev:client      # הלקוח על http://localhost:5173
```

כדי לשחק מטלפונים באותה רשת, פתחו את הכתובת שמופיעה תחת `Network` בטרמינל של הלקוח.
אפשר לבדוק לבד עם כמה לשוניות - כל לשונית היא שחקן נפרד.

### הרצה בנוסח פרודקשן

```bash
npm run build && npm start    # הכל על http://localhost:3001
```

## פריסה בחינם

**Render (מומלץ, שירות אחד):** חברו את הריפו ל-Render. הקובץ `render.yaml` כבר מגדיר הכל
(Build: `npm run build`, Start: `npm start`). השרת מגיש גם את הלקוח.

**Vercel ללקוח + Render לשרת:** ב-Vercel הגדירו Root Directory = `client`,
ומשתנה סביבה `VITE_SERVER_URL` = כתובת השרת ב-Render. (Vercel לא מריץ שרתי WebSocket קבועים, לכן השרת צריך להיות ב-Render.)

> בתוכנית החינמית של Render השרת "נרדם" אחרי זמן ללא שימוש, והטעינה הראשונה יכולה לקחת כחצי דקה.
> החדרים נשמרים בזיכרון, כך שהפעלה מחדש של השרת מוחקת אותם.

## מבנה

```
server/
  index.js          Express + Socket.io, מגיש את client/dist
  rooms.js          חדרים, שחקנים, טיימרים, סנכרון מצב
  games/*.js        לוגיקת כל משחק (start / action / view / check)
client/src/
  components/       בית, חדר, לובי, טבלה סופית, רכיבים משותפים
  games/*.jsx       מסך לכל משחק
```

השרת הוא מקור האמת: הוא מחזיק את כל המצב ושולח לכל שחקן תצוגה משלו
(למשל, רק המארח רואה את הקטגוריה הסודית). שחקן שמתנתק ומתחבר מחדש חוזר אוטומטית לאותו מקום.
